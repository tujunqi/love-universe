# 恋爱第二大脑搭建教程

> 给零代码基础的人看的完整搭建指南。
> 目标：30 分钟内建好，今晚就能写下第一条。

---

## 一、先想清楚：为什么要做“第二大脑”

恋爱里最容易丢的不是大事件，是小事情。

- 她第一次说“我到家了”是哪天；
- 你们第一次一起做饭，糊的是哪道菜；
- 吵架后是谁先递的台阶；
- 她最近反复提到、但你没接住的那句话；
- 某一个下午，阳光落在哪块地板上。

这些东西不会自动留下。照片留下了画面，聊天记录留下了字，但没有人把它们缝在一起。

第二大脑就是那个“缝”的动作。

它有三个作用：

1. **记住**：把当时以为不会忘的事写下来；
2. **理解**：通过月度复盘，看见关系正在往哪里走；
3. **再生产**：从记录里长出回忆录、纪念日信、博物馆章节、视频旁白。

它不是：

- 不是监控对方的账本；
- 不是朋友圈素材库；
- 不是每天必须打卡的任务；
- 不是证明“我们很幸福”的证据。

## 二、准备：选一个工具

你只需要一个能编辑纯文本的软件。

### 方案 A：Obsidian（推荐）

优点：

- 免费，本地保存；
- 文件夹就是一个“库”，不绑定平台；
- 支持 `[[双链]]`，可以把“第一次看海”和“第二次看海”连起来；
- 插件多，但不用插件也能用。

缺点：

- 第一次打开有点空，需要自己建文件夹；
- 同步需要额外方案（iCloud / OneDrive / Syncthing）。

### 方案 B：Typora

优点：

- 所见即所得，像 Word；
- 界面干净，适合写作。

缺点：

- 付费；
- 双链能力弱。

### 方案 C：VS Code

优点：

- 免费；
- 文件管理清晰；
- 适合已经写代码的人。

缺点：

- 默认不是“写作界面”，需要装 Markdown 预览插件。

### 方案 D：记事本 / 文本编辑

优点：

- 任何电脑都有；
- 不会因为软件停更而打不开。

缺点：

- 没有预览；
- 容易忘保存；
- 中文编码要手动选 UTF-8。

### 方案 E：Notion / 飞书 / 语雀

优点：

- 多端同步；
- 排版好看；
- 适合分享。

缺点：

- 数据在平台；
- 导出后格式会乱；
- 十年后平台还在不在，不确定。

**建议**：主库用 Obsidian 或本地 Markdown，云端只做备份，不做唯一副本。

## 三、建库：10 分钟

### 3.1 复制模板

项目里已经准备好了：

```text
brain/
├─ README.md
├─ templates/
├─ examples/
├─ daily/
├─ monthly/
├─ anniversaries/
└─ people/
```

如果你只想用现成的，直接把整个 `brain/` 文件夹复制到你的文档目录。

### 3.2 用 Obsidian 打开

1. 下载并安装 Obsidian（obsidian.md）；
2. 打开后点 `Open folder as vault`；
3. 选择 `brain/` 文件夹；
4. 如果提示“Trust author”，选信任（这是你自己的文件夹）。

你会看到左侧的文件列表。

### 3.3 建四个空文件夹

如果复制的是空目录，确认这四个文件夹存在：

- `daily/`：每日 / 每次约会；
- `monthly/`：月度复盘；
- `anniversaries/`：纪念日；
- `people/`：喜好清单、家人朋友。

没有就右键新建。

### 3.4 设置模板（可选）

Obsidian 自带“模板”核心插件：

1. 设置 → 核心插件 → 打开“模板”；
2. 模板文件夹设为 `templates/`；
3. 新建笔记后，按 `Ctrl/Cmd + P`，搜索“插入模板”。

不想折腾也行，直接复制模板文件。

## 四、Markdown 速成：只需要 8 个语法

第二大脑不需要复杂排版。记住这些就够：

### 1. 标题

```markdown
# 一级标题
## 二级标题
### 三级标题
```

### 2. 加粗和斜体

```markdown
**加粗**
*斜体*
```

### 3. 列表

```markdown
- 第一条
- 第二条
  - 子条目
```

### 4. 引用

```markdown
> 她说：“我今天很累。”
```

引用最适合放原话。

### 5. 分隔线

```markdown
---
```

### 6. 链接

```markdown
[显示的文字](https://example.com)
```

### 7. 图片

```markdown
![照片说明](../assets/photos/2025-10-24-阳台.jpg)
```

路径是相对于当前 `.md` 文件的位置。

### 8. 双链（Obsidian）

```markdown
[[01-在一起的第一晚]]
[[2024-09-17-第二次看海]]
```

输入 `[[` 会自动弹出文件名。

> 不需要学 HTML、CSS、数据库。Markdown 就是“给文字加一点点标记”。

## 五、写第一条：今晚 10 分钟

### 5.1 复制模板

把 `templates/01-每日约会记录模板.md` 复制到 `daily/`。

### 5.2 重命名

```text
2026-10-25-她来公司楼下等我.md
```

规则：

```text
YYYY-MM-DD-一句话标题.md
```

标题写具体的事，不写“开心的一天”。

### 5.3 只填三个空

第一次不要填满。只写：

1. **一个画面**：在哪里，谁在做什么；
2. **一句原话**：她/他当时说了什么；
3. **一个感官细节**：气味、声音、温度、触感、味道。

例如：

```markdown
## 今天发生了什么

她来公司楼下等我。我下去的时候，她站在便利店门口，
手里拿着两瓶水，一瓶已经喝了一半。

## 原话

> 她：“你终于下来了。我都看完两集短剧了。”

## 身体记得

- 气味：便利店门口的关东煮
- 温度：她递给我的水是冰的，手心是热的
```

300 字就可以。写完保存，关掉。

### 5.4 不要做的三件事

- 不要先想“这篇要表达什么”；
- 不要用“岁月静好”“双向奔赴”；
- 不要为了让对方看到而写。

先为自己写。

## 六、30 天启动计划

不需要每天写。按这个节奏，30 天后你会有一个能回看的库。

### 第 1 周：只写画面

- 目标：3 条；
- 每条 300 字；
- 只写“在哪里、做了什么、说了什么”；
- 不写意义，不写总结。

### 第 2 周：加入感官和原话

- 目标：3 条；
- 每条至少 1 句原话、1 个感官细节；
- 开始给照片写具体说明。

### 第 3 周：写一次不完美

- 目标：1 条争吵 / 冷战 / 失望的记录；
- 不评判谁对谁错；
- 写清楚后来怎么缓和的（哪怕还没缓和）。

### 第 4 周：做一次月度复盘

- 用 `templates/02-月度复盘模板.md`；
- 30–45 分钟；
- 挑出这个月最想留下的 3 个瞬间；
- 更新一次喜好清单的“最近想要 / 最近不要”。

30 天后，你至少有 7 条日常 + 1 次复盘。
这已经足够开始做博物馆的第一版。

## 七、标签与双链：让记录找得到

### 7.1 标签不要太多

建议只用这几类：

```text
#日常
#旅行
#争吵
#纪念日
#家人
#工作
#生病
#礼物
```

标签写在 frontmatter 里：

```yaml
tags: [日常, 旅行]
```

不要给每条都加十几个标签。标签是抽屉，不是装饰。

### 7.2 双链怎么用

三种最有用：

1. **时间链**：昨天 → 今天 → 明天；
2. **事件链**：第一次看海 → 第二次看海；
3. **人物链**：所有和小满有关的记录，都链到 `[[小满]]`。

示例：

```markdown
- 上一次：[[2024-09-17-第二次看海]]
- 这一次：[[2025-07-20-第三次看海]]
- 人物：[[小满]]
```

### 7.3 地点也可以做笔记

给常去的地方各建一条：

```text
places/城西的咖啡馆.md
places/海边的防波堤.md
places/楼下的便利店.md
```

里面写：

- 第一次去是什么时候；
- 坐在哪个位置；
- 点什么；
- 发生过什么。

以后写记录时，直接链过去。

## 八、照片、语音、视频怎么放

### 8.1 目录建议

```text
brain/
├─ assets/
│  ├─ photos/
│  ├─ voice/
│  └─ video/
```

按日期命名：

```text
assets/photos/2025-10-24-阳台.jpg
assets/voice/2025-10-24-她收衣服.m4a
```

### 8.2 在 Markdown 里引用

```markdown
![她收衣服时，风把窗帘吹到了她脸上](../assets/photos/2025-10-24-阳台.jpg)
```

照片说明要具体：

- 不要写“日常”；
- 写“她收衣服时，风把窗帘吹到了她脸上”。

### 8.3 不要把原图只放在手机里

手机相册会丢、会换、会满。

建议每月一次：

1. 把当月照片导出到 `assets/photos/`；
2. 删除模糊、重复的；
3. 给保留的照片写一句说明；
4. 备份到移动硬盘。

### 8.4 语音比照片更容易被忘记

微信语音会过期，手机录音会丢。

重要的语音（生日、道歉、日常碎碎念）导出成 MP3 / M4A，
放进 `assets/voice/`，在记录里链上。

## 九、月度复盘怎么开

### 9.1 时间

找一个双方都不赶时间的晚上，30–45 分钟。

不要在床上，不要在吵架后，不要在孩子/家人旁边。

### 9.2 流程

1. 各自先写 10 分钟（用模板）；
2. 交换看，不打断；
3. 每人说一个“这个月我最想感谢你的瞬间”；
4. 每人说一个“这个月我有点难受的瞬间”；
5. 不辩论，只确认“我听到了”；
6. 一起定下个月的三件事；
7. 做一件小事：散步、吃水果、洗碗。

### 9.3 三条规则

- **不打分**：不要给“本月男友表现”打分；
- **不翻旧账**：只谈这个月；
- **不逼问**：可以拒绝回答，不要追问。

### 9.4 复盘后做什么

- 把复盘文件存进 `monthly/`；
- 把其中值得进博物馆的片段标记出来；
- 更新喜好清单；
- 如果发现一个反复出现的问题，单独建一条 `problems/` 笔记，写下下一次的具体做法。

## 十、从记录到成品

### 10.1 选材

每月从 `daily/` 里挑：

- 1 个平常瞬间；
- 1 个开心瞬间；
- 1 个不太好但已经走出来的瞬间。

不要只挑甜的。博物馆里有一章吵架，反而更真。

### 10.2 改成博物馆章节

一条日常记录 → 一章回忆录：

1. 保留原话；
2. 删掉重复的解释；
3. 补一个当时的环境细节；
4. 结尾不要总结，留一个动作或一句话。

### 10.3 改成主页时间线节点

时间线只需要：

- 日期；
- 一句标题；
- 一段 80–150 字的描述；
- 一个图标 / 照片。

从记录里直接摘。

### 10.4 做成纪念日信

把一年的记录按时间排开，找出：

- 今年最常出现的场景；
- 今年重复最多的一句对话；
- 今年变化最大的地方。

用这三样做骨架，比空想“写点什么”容易得多。

## 十一、和 AI 一起整理

### 11.1 能做什么

- 把零散聊天整理成一篇有场景的回忆；
- 把照片描述扩写成说明；
- 把一年的记录压缩成月度复盘；
- 把争吵记录整理成“事实 / 感受 / 需求 / 下次做法”；
- 把回忆录改得更口语、更少套话。

### 11.2 不能做什么

- 不能替你编细节；
- 不能替你们和好；
- 不能判断谁对谁错；
- 不能保证隐私。

### 11.3 安全做法

1. 先删掉地址、公司、学校、身份证、车牌、账号；
2. 不要上传私密照片；
3. 用“阿星 / 小满”这样的化名；
4. 如果内容很私密，用本地模型（如 Ollama）而不是云端；
5. AI 输出后，自己逐句改，删掉不像你们的话。

完整指令见 [Agent 整理指令](07-Agent整理指令.md)。

## 十二、隐私、加密与备份

### 12.1 隐私

- Markdown 是纯文本，没有加密；
- 网盘会自动同步、扫描、留存；
- 聊天记录截图可能带对方头像、昵称、时间；
- 照片可能带 EXIF 地理位置。

### 12.2 加密

三种方案：

1. **压缩包加密**：7-Zip → AES-256 → 密码单独保存；
2. **加密盘**：VeraCrypt 创建一个加密容器；
3. **系统加密**：BitLocker（Windows）/ FileVault（macOS）。

日常写作不建议每次都加密（麻烦），
但**备份文件**和**含敏感信息的文件**应该加密。

### 12.3 备份：3-2-1

- 3 份副本；
- 2 种介质（电脑硬盘 + 移动硬盘 / U 盘）；
- 1 份异地（加密云盘 / 另一处房子）。

每月一次，每季度检查一次能不能打开。

### 12.4 版本

每次大改之前，复制一份：

```text
brain-backup-2026-10-25/
```

不要依赖“我记得改了什么”。

## 十三、常见问题

**Q：坚持不下来怎么办？**
A：把目标降到“一周一条”。第二大脑不是打卡，空一个月也不会坏。

**Q：写着写着像流水账？**
A：流水账没问题。先有事实，再谈文采。挑一个画面展开，其他一句带过。

**Q：对方不愿意被记录？**
A：尊重。可以只写自己的感受，不写对方的私事；或者只做共同可见的部分。

**Q：可以只用手机吗？**
A：可以。Obsidian 手机版、备忘录、Markdown 编辑器都行。但长期保存建议回到电脑。

**Q：要不要每天问对方“今天怎么样”？**
A：可以，但不要像采访。先分享自己的一天，再自然地问。

**Q：记录吵架会不会加深矛盾？**
A：看怎么写。写“事实 + 我的感受 + 我希望下次怎么做”，不要写“她又无理取闹”。

**Q：AI 整理后太像公文？**
A：把 AI 写的形容词全删掉，只留动作和原话，再读一遍。

**Q：需要同步到云端吗？**
A：需要异地备份，但不必实时同步。实时同步会增加误删和隐私风险。
