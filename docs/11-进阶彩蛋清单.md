# 11 · 进阶彩蛋清单

> 彩蛋不是「功能越多越好」，而是**让对方在某个瞬间意识到：这个东西是专门为我做的**。
>
> 下面这些彩蛋，大部分已经写好并可以触发；少数需要你补一段视频、一段语音或一次部署。
> 每一条都标了「怎么触发」「改哪里」「风险」，照着做即可。

## 1. 封面标题连点 5 下：一句很轻的提示

**怎么触发**：在 4 秒内连续点击封面大标题「我们的第 X 天」5 次。

**会发生什么**：

- 屏幕中央炸开一小簇心；
- 顶部出现提示：「提示：页脚藏着一封需要密码的信。」

**改哪里**：

- `js/main.js` 的 `initCover()` 里，`titleClicks.length >= 5`；
- 想改成 3 下就改数字；
- 想改提示语，改 `toast("提示：页脚藏着一封需要密码的信。")`。

**适合**：第一次访问，给愿意乱点的人一条线索。

**风险**：点太多会烦。5 下是一个刚好的数字，别再增加。

## 2. 页脚小爱心点 7 下：只给有耐心的人

**怎么触发**：滚到页面最底部，在 4 秒内点击右下角那个不显眼的 `♡` 7 次。

**会发生什么**：

- 每次点击都会炸出几颗心；
- 第 7 下出现一行隐藏的话：

```text
今天也偷偷多爱你一点。这是只有点满七下的人才能看到的话。
```

**改哪里**：

- 隐藏的话在 `js/main.js` 的 `CONFIG.hiddenMessage`；
- 触发次数在 `initSecrets()` 的 `clicks.length >= 7`；
- 时间窗口是 `now - time < 4000`（4 秒）。

**适合**：放在页脚，不打扰主流程；只有真的把页面看到最后的人才会发现。

**风险**：手机上没有「悬停」，只能靠点。图标已经做得比较小，不要做得完全看不见。

---

## 3. 密码信：页脚的那封信

**怎么触发**：

1. 滚到页脚；
2. 点击「有一封只写给你的信」；
3. 输入你们在 ⚙ → 信里设置的密码，或者答对 3 道默契题；
4. 回车。

**会发生什么**：

- 弹出一封按段落排版的长信；
- 解锁状态会保存在当前浏览器，下次打开不用再输；
- 改了密码、解锁方式或信的内容后，旧的解锁状态会自动失效；
- 输错会提示「密码不对。再想想那个日子。」并清空输入框。

**改哪里**：

- 最快：页面右上角 ⚙ → 信；
- 密码：`js/main.js` 的 `CONFIG.secretPassword`；
- 解锁方式：`CONFIG.unlockMode`，可填 `password` 或 `quiz`；
- 信件标题、落款、段落：`CONFIG.letter`；
- 页脚入口文字：`index.html` 里 `#secretEntry`；
- 想换密码提示，改信弹层里的说明文字。

**适合**：把最重要的话放在最后，而不是第一屏。

**风险**：

- 这只是**前端校验**，不是加密。任何人查看网页源码都能看到密码和内容。
- 不要在这里放身份证、住址、私密照片。
- 改密码后，记得把旧密码提示一起改掉，否则对方会一直试旧密码。

## 4. 隐藏视频：把一段视频放进信里

**状态**：代码已经留好位置，但默认没有视频文件。直接点播放会显示「视频还没放进来」的提示。

**怎么加**：

1. 把视频命名为 `secret.mp4`；
2. 放进 `assets/video/`（没有这个文件夹就新建）；
3. 确认 `js/main.js` 的 `CONFIG.secretVideo` 是 `"assets/video/secret.mp4"`；
4. 打开页面 → 解锁信 → 点播放。

**会发生什么**：

- 视频只有在点击播放时才会加载，不会拖慢首页；
- 没有文件时，会显示一个温和的占位提示，不会报错。

**适合**：一段 30 秒的日常视频、一句当面说不出口的话、一次旅行的片段。

**注意**：

- 视频建议压到 20MB 以内，H.264 + AAC，兼容性最好；
- 不要放未经对方同意的私密视频；
- 公网部署时，视频 URL 是可以被直接访问的，密码挡不住；
- 如果视频很大，考虑放 U 盘版，而不是公网。

## 5. 生日自动弹层：当天打开就有

**怎么触发**：在 10 月 16 日打开主页，等 1.5 秒。

**会发生什么**：

- 自动弹出「生日快乐，我最喜欢的人」；
- 显示一段祝福；
- 背景炸开三簇心；
- 同一天只弹一次（刷新也不会重复烦人）。

**改哪里**：

- `CONFIG.birthday.monthDay`：改成对方的生日，格式 `MM-DD`；改成 `""` 可关闭；
- `CONFIG.birthday.title` / `message`：祝福语；
- 想立刻预览，不等到生日：在网址后面加 `?preview=birthday`。

**适合**：生日当天对方自己打开网站时，第一眼就收到。

**风险**：

- 只在**当天**触发，错过就没了；
- 依赖对方打开页面，不会主动推送；
- 预览参数 `?preview=birthday` 会绕过日期判断，公开部署前要知道它的存在。

## 6. 三套主题与链接记忆

**怎么触发**：

- 右上角的主题按钮：温柔粉 / 夜空蓝 / 复古棕；
- 或在网址后加 `?theme=night`、`?theme=retro`、`?theme=rose`。

**会发生什么**：

- 切换后整个页面的颜色、光晕、粒子、阴影都会变；
- 选择会保存在当前浏览器，下次打开还是上次的主题；
- 用链接参数可以强制打开某个主题，适合截图或做不同的发送版本。

**改哪里**：

- 默认主题：`CONFIG.defaultTheme`；
- 三套主题的变量：`css/style.css` 顶部 `html[data-theme="rose"]` 等；
- 主题列表与颜色：`js/main.js` 的 `THEME_META`。

**适合**：

- 给同一个人做三个版本：「白天看粉的，晚上看蓝的，纪念日看棕的」；
- 在发送话术里写：「晚上再点一次，有另一个颜色。」

**风险**：改 CSS 变量时，注意对比度；夜空蓝下的深色文字可能看不清。

## 7. 心跳计数：每一次点击都算数

**怎么触发**：点封面上的心跳按钮。

**会发生什么**：

- 数字加一；
- 按钮跳动、粒子散开；
- 随机出现一句「咚。收到一次心动。」「今天也喜欢你。」之类的话；
- 计数保存在当前浏览器，下次打开还在。

**改哪里**：

- 情话数组：`initHeartButton()` 里的 `heartLines`；
- 按钮文案：`index.html` 的 `#heartBtn` 附近；
- 想清零：浏览器开发者工具 → Application → Local Storage → 删除 `loveUniverse.v1.heartCount`。

**适合**：让对方知道「你点的每一下我都收下了」。

**风险**：换浏览器/换设备数字不会同步；不要把它说成「云端计数」。

## 8. 抽签计数与默契最高分

**两个小记录**：

1. **抽情话**：每次抽签，页面上会显示「已经抽了 X 次」，数字存在本地；
2. **默契测试**：支持两人分别作答，也支持标准答案模式；做完会给分数和评语，本机最高纪录会保存；满分时会有一次小小的庆祝。

**怎么触发**：

- 抽签：情话卡片上的「再抽一次」；
- 测试：最后一题选完自动出结果。

**改哪里**：

- 50 条情话：`CONFIG.quotes`；
- 5 道题：`CONFIG.quiz`；
- 评语：`initQuiz()` 里的 `comments`；
- 满分庆祝：`score === questions.length` 分支。

**适合**：增加「玩过」的痕迹，而不是每次都从零开始。

**风险**：

- 记录只在本地，换设备会消失；
- 题目答案写在 JS 里，懂技术的人可以直接看；
- 不要用测试分数评判对方爱不爱你。

## 9. 博物馆时间胶囊：等到 2035 年

**怎么触发**：

- 打开离线博物馆 → 进入「时间胶囊」展厅；
- 输入密码 `0520`；
- 或等到 `2035-05-20T20:13:00` 自动打开；
- 预览：在网址后加 `?preview=capsule`。

**会发生什么**：

- 先看到倒计时（天/时/分/秒）；
- 输入正确密码后，展开一封写给 2035 年的信；
- 解锁状态保存在当前浏览器；
- 到达约定时间后，胶囊自动打开。

**改哪里**：

- `offline/museum.js` 的 `MUSEUM.capsule`：
  - `openDate`：打开时间；
  - `password`：密码；
  - `title` / `intro` / `paragraphs` / `sign`：信的内容。

**适合**：把「现在想说的话」留给未来的你们。

**风险**：

- 密码同样是前端校验，不是加密；
- 修改 `openDate` 后，如果之前已经解锁过，本地状态仍然是「已打开」；需要清 localStorage 或换浏览器测试；
- 如果 U 盘丢失，胶囊也跟着丢；记得备份；
- 不要放需要保密的内容。

## 10. 博物馆直达入口：跳过封面

**怎么触发**：在博物馆网址后加参数：

```text
?skipboot=1              跳过启动页，直接进序厅
?view=hall               跳过启动页，停在序厅
?view=gallery            直接到照片墙
?view=screen             直接到放映厅
?view=memoirs            直接到回忆录
?view=capsule            直接到时间胶囊
?view=guide              直接到参观指南
?preview=capsule         直接打开胶囊（绕过倒计时和密码）
```

**适合**：

- 自己调试时省时间；
- 把「直接看照片墙」的链接单独发给对方；
- 做展览时固定停在某个展厅。

**风险**：

- 这些是调试入口，公开部署前要知道它们能绕过封面和密码；
- 如果不想让对方看到，可以在 `museum.js` 里删掉 `params` 相关分支，或至少在发送时不要提。

## 11. U 盘图标、启动页与全屏展厅

**三个层次**：

1. **图标**：U 盘插上后显示金色相框 + 月亮 + 两个人的剪影（`offline/museum.ico`）；
2. **启动页**：打开后先看到「我们的私人博物馆」封面，点「进入」才进展厅；
3. **全屏**：`offline/全屏参观.bat` 用 kiosk 模式打开，没有地址栏，像一个小展览。

**怎么用**：

- 参考 [05-开机画面与自动运行.md](05-开机画面与自动运行.md)；
- 想换成你们的照片：用 `tools/make-icon.js` 重新生成图标；
- 全屏脚本会优先找 Chrome/Edge，找不到就用默认浏览器。

**适合**：当面送 U 盘、纪念日摆在桌上、朋友来家里时展示。

**风险**：

- Windows 10/11 默认不允许 U 盘 AutoRun，插上不会自动播放；
- kiosk 模式退出要 `Alt + F4`，先自己试；
- 图标缓存可能需要重新插拔 U 盘才会更新。

## 12. 单文件离线版：一个 HTML 就是一座博物馆

**怎么触发**：双击：

```text
offline/单文件版/恋爱纪念博物馆-单文件版.html
```

**会发生什么**：

- 不需要 `museum.css`、`museum.js`、`media/` 文件夹；
- 照片、封面、音乐、语音、文档全部内嵌为 data URI；
- 断网、换电脑、放 U 盘、发邮件都能打开；
- 文档链接仍然可以下载。

**怎么做**：

```bash
node tools/build-single-file.js
```

想连视频一起嵌进去：

```bash
node tools/build-single-file.js --embed-video
```

**适合**：对方电脑没有整个文件夹、只想发一个文件、做长期备份。

**风险**：

- 文件会变大（当前约 3MB，加视频会大很多）；
- 浏览器打开 3MB 以上的 HTML 可能慢一两秒；
- 内嵌的密码仍然是前端校验；
- 修改素材后要重新生成，不会自动同步。

## 13. 本地记忆的连续性：她来过，就会留下痕迹

**这些状态都保存在浏览器 localStorage 里**：

- 主题选择；
- 心跳次数；
- 抽签次数；
- 默契测试最高分；
- 留言板内容；
- 信是否解锁；
- 生日弹层今天是否已弹；
- 博物馆胶囊是否已打开。

**为什么算彩蛋**：

对方第二次打开时，页面不是「重新开始」，而是「接着上次」。
她点过的心、抽过的签、留下的言，都还在。

**适合**：长期使用，而不是一次性礼物。

**风险**：

- 换浏览器、换手机、清理缓存会丢失；
- 不会跨设备同步；
- 不要把它宣传成「云端保存」；
- 想长期保存留言，最好同时导出一份到第二大脑。

## 14. 小助手的「今天的小事」

**怎么触发**：

```bash
python love_assistant.py --scene night --note "她今天加班到十点"
```

或者菜单 3 → 选场景 → 输入今天的小事。

**会发生什么**：

- 生成的 3 条情话里，至少有一条会提到这件事；
- 不是简单拼接，而是从带 `{note}` 的模板里挑一句；
- 可以加 `--save` 保存到 `assistant/out/`。

**适合**：当天发生了一件小事，想让它出现在晚安里。

**风险**：

- 模板是固定的，句子可能不完全自然；发送前一定自己读一遍；
- `--note` 会被写进生成文本，不要放敏感信息；
- 它不会自动发送，只负责生成。

## 15. 可扩展：定时早安消息

**思路**：

1. 用任务计划程序每天 07:30 运行：

   ```text
   python love_assistant.py --scene morning --save
   ```

2. 生成的文件落在 `assistant/out/`；
3. 把 `out/` 放进 OneDrive/坚果云，手机上打开最新文件；
4. 或写一个邮件脚本，把文本发到自己的邮箱。

**为什么不做「自动发微信」**：

- 微信个人号没有官方自动发消息接口；
- 第三方工具可能违反平台规则，也可能导致账号受限；
- 需要保持登录，隐私风险高。

**可选的小变化**：

- 每天加 `--seed` 用日期做种子，保证同一天内容稳定；
- 周五用 `--scene night`，周末用 `--scene morning`；
- 重要日子前一周，用 `--note` 提醒自己准备。

## 16. 给未来读者的信

**怎么触发**：打开离线博物馆 → 「馆藏文档」→《给未来读者》。

**会发生什么**：

- 一篇写给几十年后打开这个 U 盘的人的信；
- 说明怎么打开、密码提示、格式迁移、备份建议；
- 可以直接下载为 TXT。

**改哪里**：

- 文件：`offline/media/memoirs/给未来读者.txt`；
- 登记：`offline/museum.js` 的 `MUSEUM.documents`；
- 单文件版需要重新生成才会更新。

**适合**：把 U 盘当成「时间胶囊」，而不只是一次性的礼物。

**风险**：

- TXT 是最稳的格式，但不要只留一份；
- 改完记得重新生成单文件版；
- 不要在里面写密码的明文，除非你接受任何捡到 U 盘的人都能看。

## 彩蛋设计的三条原则

### 1. 不打扰主流程

彩蛋应该藏在边上：页脚、标题、第二次点击、某个参数。
不要在第一屏弹三个窗口，也不要在对方想关页面时拦住她。

### 2. 有线索，但不考试

- 线索要足够明显：点 5 下标题会提示「页脚有信」；
- 密码提示要能让人想起来：用对你们有意义的四位数字，并在页面上留一句提示；
- 不要让对方猜半小时，也不要把「猜不到」当成不爱。

### 3. 不制造负罪感

- 不要写「不点开就是不爱我」；
- 不要用倒计时逼对方；
- 不要在对方没空时反复提醒；
- 不要用「我做了这么久」换取感动。

- [ ] 确认公网链接不会被搜索引擎收录（必要时加 `robots.txt` 或访问密码）；
- [ ] 确认 U 盘里没有其他私人文件；
- [ ] 自己用手机、平板、别人的电脑各打开一次；
- [ ] 把彩蛋线索写在一张纸上，和礼物一起给对方（可选）；
- [ ] 准备好「对方不想看」时的退路。

---

## 最后

彩蛋的本质不是技术，是**你愿意为一个人多走一步**。
但多走的那一步，应该是让对方更轻松，而不是更有压力。

如果只能记住一句话：

> 最好的彩蛋，是对方发现之后，觉得「你真的很懂我」，而不是「你真的很会做网页」。
