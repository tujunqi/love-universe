# 恋爱第二大脑 · 使用说明

> 这不是一个“秀恩爱素材库”，也不是监控对方的账本。
> 它只做一件事：把你们一起经历过的普通日子，留下来。

---

## 一、它是什么

一个用 Markdown 写的本地文件夹。

- 每一条记录都是一个 `.md` 文件，用任何文本编辑器都能打开；
- 不需要联网、不需要数据库、不需要 App；
- 可以用 Obsidian、Typora、VS Code、甚至记事本阅读；
- 照片、语音仍然放在文件夹里，用相对路径链接；
- 十年后，即使软件没了，文字还在。

它和项目里其他部分的关系：

```text
恋爱纪念宇宙/
├─ index.html              ← 给别人看的“成品”
├─ offline/                ← U 盘里的“博物馆”
├─ brain/                  ← 你每天写的“原料库”（本文件夹）
├─ assistant/              ← 本地 Python 小助手
└─ docs/                   ← 教程
```

**第二大脑是原料，主页和博物馆是成品。**
先把日子写下来，再从中挑出值得展示的部分。

## 三、10 分钟开始

### 第 1 步：选一个编辑器

任选一个：

| 工具 | 适合谁 | 备注 |
| --- | --- | --- |
| Obsidian | 想长期用、喜欢双链 | 免费，本地文件夹就是一个库 |
| Typora | 想所见即所得 | 付费，但很轻 |
| VS Code | 已经写代码 | 免费，插件多 |
| 记事本 / 文本编辑 | 只想先试试 | 够用，注意保存为 UTF-8 |

### 第 2 步：打开这个文件夹

- Obsidian：`Open folder as vault` → 选择 `brain/`
- VS Code：`File → Open Folder` → 选择 `brain/`
- Typora：直接打开任意 `.md` 文件

### 第 3 步：复制模板

把 `templates/01-每日约会记录模板.md` 复制到 `daily/`，
重命名为：

```text
2026-10-25-她来我公司楼下等我.md
```

命名规则：

```text
YYYY-MM-DD-一句话标题.md
```

一句话标题写具体的事，不要写“开心的一天”。

### 第 4 步：只填三样

第一次不要追求完整，只填：

1. 今天的一个画面；
2. 对方的一句原话；
3. 一个感官细节（气味、声音、温度、触感、味道）。

300 字就可以。写完就关掉。

### 第 5 步：一周后回看

周末翻一遍这周写的三条，挑一条补充：

- 当时没写完的话；
- 一张照片；
- 一个后来才知道的后续。

第二大脑不是打卡，是回看。

## 四、四种记录，四种用途

### 1. 每日 / 每次约会（`daily/`）

- 频率：有值得记的就写，不强制每天；
- 长度：300–800 字；
- 重点：具体画面、原话、感官细节；
- 用途：日后写回忆录、做博物馆、回答“我们以前是什么样”。

### 2. 月度复盘（`monthly/`）

- 频率：每月一次，30–45 分钟；
- 长度：1000–2000 字；
- 重点：状态、争吵与修复、生活底盘、下月三件事；
- 用途：防止日子糊在一起，及时发现关系里的偏移。

### 3. 纪念日（`anniversaries/`）

- 频率：每年一次；
- 长度：1500–3000 字；
- 重点：今年的变化、最难/最想重播的一天、互相采访、给明年写信；
- 用途：年度锚点，也是最好的礼物原料。

### 4. 喜好清单（`people/`）

- 频率：建立一次，每季度更新；
- 重点：吃、穿、感官、情绪说明书、礼物、边界；
- 用途：少一点想当然，多一点照顾；
- 前提：对方知情并同意。

## 五、写作原则

### 1. 先写事实，再写意义

不要一上来就写“今天很幸福”。先写：

- 几点；
- 在哪里；
- 谁做了什么；
- 说了什么；
- 天气怎样；
- 当时在放什么歌。

意义可以最后再补，也可以不补。

### 2. 保留原话

“她说她没事”不如：

> “她说‘没事’，但把杯子放得很重。”

原话里有人物的性格、语气和当时的空气。

### 3. 记录不完美

争吵、冷战、迟到、忘记纪念日、说了难听的话，都可以写。

只写甜的部分，十年后你会觉得那不是你们。
写清楚“后来怎么缓和的”，比假装没发生更有用。

### 4. 一个细节胜过十个形容词

不要写“她很温柔”，写：

> 我咳嗽的时候，她把水杯往我这边推了两厘米，没说话。

### 5. 不替对方写内心

可以写“我猜”“我感觉”“她后来告诉我”，
不要写“她当时一定在想……”。

### 6. 允许空白

有些日子不想写，就不写。
第二大脑不是绩效考核。

## 六、和 AI 一起整理

你可以把零散的聊天记录、朋友圈文案、照片描述交给 AI，
让它整理成一篇完整的回忆文档。

项目里给了完整的 Agent 指令：

- `docs/07-Agent整理指令.md`

核心规则只有三条：

1. **不许编。** 没发生的事不要补，不确定的写 `[待确认]`；
2. **保留原话和细节。** 不要把“她把杯子放得很重”改成“她有些不满”；
3. **输出要像人写的。** 不要用“岁月静好”“双向奔赴”这类空词。

推荐流程：

```text
零散素材 → AI 整理初稿 → 你自己删改 → 存入 daily/ → 月度回看 → 选入博物馆
```

AI 是助手，不是替你们谈恋爱的人。
最后一遍必须你自己改。

## 七、隐私与安全

### 必须知道

- Markdown 是纯文本，**没有任何加密**；
- 放到网盘、微信、云笔记，就等于交给了平台；
- 截图、聊天记录、照片里可能带地址、学校、公司、车牌；
- AI 云端模型会接收你粘贴的内容。

### 建议

1. 第二大脑只放本地，或放加密盘；
2. 敏感内容（身份证、住址、账号、私密照片）不要放进来；
3. 真要放，使用 VeraCrypt / 7z 加密压缩包，密码单独保存；
4. 给对方看之前，先问一句“这段我可以记吗”；
5. 不记录对方的行踪、聊天对象、密码；
6. 每季度做一次备份：本地 + 移动硬盘 + 加密云盘。

### 一条底线

**第二大脑是你们共同的，不是其中一个人的侦查档案。**
如果对方不愿意被记录，尊重她。

## 八、维护节奏

### 每周（10 分钟）

- 翻一遍本周记录；
- 补 1–2 个细节；
- 把照片文件名补上。

### 每月（30 分钟）

- 写月度复盘；
- 更新喜好清单里“最近想要 / 最近不要”；
- 把值得进博物馆的片段标记出来。

### 每年（2 小时）

- 写纪念日记录；
- 从全年记录里挑 20 张照片、6 个章节；
- 更新 `offline/museum.js` 和 `js/main.js`；
- 重新生成单文件版；
- 做一次完整备份。

### 每五年（半天）

- 迁移文件格式；
- 检查旧硬盘 / U 盘是否还能读；
- 更新密码和备份位置；
- 重读一遍以前的记录。

## 九、常见问题

**Q：每天都要写吗？**
A：不用。有值得记的就写。一个月 4–8 条已经很好。

**Q：写不出来怎么办？**
A：只回答三个问题：今天在哪里？她说了什么？有什么味道/声音？

**Q：可以只写甜的么？**
A：可以，但建议至少保留一次争吵或低谷。完整比完美重要。

**Q：对方偷看怎么办？**
A：如果这是共同空间，提前说清楚哪些可以看。需要私人空间，就分开存。

**Q：用 Notion / 飞书文档可以吗？**
A：可以，但导出和长期保存不如本地 Markdown 稳。建议本地留一份。

**Q：AI 整理后不像我们说话怎么办？**
A：把原话贴回去，删掉所有形容词，只留动作和对话。

## 十、从记录到成品

一条记录可以变成：

- 主页时间线上的一个节点；
- 博物馆回忆录的一章；
- 纪念日视频的旁白；
- 一封信的开头；
- 吵架后复盘的事实依据；
- 很多年后，你们坐在沙发上随机翻开的一页。

不要为了“做成成品”而写。
先写，成品会自己长出来。
